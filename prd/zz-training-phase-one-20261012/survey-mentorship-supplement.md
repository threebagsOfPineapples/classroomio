# 至臻培训一期问卷带教与钉钉扫码补充说明

状态：需求补充，已开始实施。初稿日期：2026-10-12；决策更新：2026-10-13。适用对象：培训部与数智团队。主方案：[一期方案与需求对照](README.md)。实现与验证记录见[本轮功能实现记录](implementation-20261013.md)。

一期需完成独立培训需求调研、课后扫码评价、导师带教及持续督办。扫码入口采用手机版 H5，沿用钉钉账号与现有人事系统接入；二维码只负责打开任务，身份、参与资格和提交结果由服务端校验。主管定期学习报告仍属于一期，完整岗位学习地图与人才发展按原分期推进。

本说明细化主方案第 5.3—5.6 节及 A10—A17 验收项。下文区分已明确需求、参考平台做法、建议规则与待确认制度；参考资料中的配置不能直接当作至臻已确认制度。初稿时问卷独立发放、扫码本人提交和带教完整闭环尚未实施；当前代码进展见实现记录，设计稿中的模拟操作与本地测试均不代表业务已上线。

2026-10-13 已现场核对飞书正文、角色权限和平台对标等四张表，遗漏与剩余验收见[飞书需求核对清单](feishu-requirements-audit-20261013.md)。后续仅在 119 部署测试，101 暂不处理。

## 2 问卷调查的业务设计

### 2.1 问卷内容与发放任务分开

问卷模板负责题目与版本；发放任务负责用途、对象、时间、入口与回收。先编辑并发布模板，再引用固定版本创建发放任务。同一模板可以复用到多个部门或培训场次，历史答卷仍保留原题目与选项。

培训需求调研用于收集所需课程、岗位难点、培训方式与可参与时间；课后评价用于收集课程满意度、讲师评价、应用意愿与改进意见。两者共用问卷引擎，但用途、对象与统计分开。培训需求调研无需先建课程，课后评价不沿用旧功能“培训结业后才能评价”的统一限制。

一期题型建议采用单选、多选、评分、文本与必答设置，满足现阶段需求。复杂跳题、矩阵题等不自动追加为一期必做项。

### 2.2 参与范围与分发渠道分开

| 维度 | 规则 | 示例 |
| --- | --- | --- |
| 参与范围 | 指定部门、人员，或允许总部范围内自由填写 | “客服一部受邀员工”或“总部员工均可填写” |
| 分发渠道 | 学员待办、钉钉工作通知、二维码、链接，可以同时使用 | 同一份定向问卷既发通知，也在培训现场展示二维码 |
| 身份方式 | 实名或匿名，发布前固定并向学员说明 | 实名用于个别跟进，匿名用于意见收集 |

定向问卷扫码后仍检查受邀资格；二维码转发给其他部门不会产生新资格。按部门及岗位筛选时明确交集，发布前展示实际名单；更复杂的并集规则沿用主方案的显式配置。

总部内部自由填写与外部开放调研不同。一期不因授客支持跨组织分享而增加外部访客账号。定向任务固定受邀名单快照，后续追加、撤销资格有原因和记录。

### 2.3 发布与填写流程

培训岗流程：编辑模板 → 发布版本 → 建发放任务 → 设置对象、实名或匿名、时间 → 核对实际名单 → 发布 → 获取二维码和链接 → 查看回收、提醒与导出。为一名培训岗提供模板复制和发布向导，减少反复建题。

学员流程：待办或扫码进入 → 识别本人身份 → 校验任务与资格 → 查看用途及匿名说明 → 填写与保存草稿 → 提交 → 查看成功回执。未登录时返回原任务；无资格、未开放、已关闭、已提交和请求失败分别展示，不返回空白页。

建议同一发放任务、同一员工只有一份正式答卷。草稿可修改；是否允许提交后在截止前改答待确认。若开放重答，应保留历史与修订记录，不直接覆盖旧答案。重复点击、网络重试和多端同时提交不能增加回收人数。

评价是否限已签到或已学完人员，由发放时的资格规则决定，待业务确认；不能把签到成功自动视为已经评价。

### 2.4 匿名与统计

实名问卷可按授权范围查看答卷与员工。匿名问卷可在独立参与记录中判断是否提交，以支持去重和催答，但答案与员工身份不能通过普通管理接口、导出或日志关联反查。匿名小样本的部门统计阈值及自由文本展示范围需另行确认，不能承诺完全无法从内容推断身份。

| 指标 | 计算口径 |
| --- | --- |
| 定向问卷回收率 | 已正式提交的受邀员工去重人数 / 有效受邀员工数；同时显示分子、分母与统计时点 |
| 总部内部自由填写 | 无固定受邀名单时显示答卷数、参与人数与期间，不生成无依据的回收率 |
| 单选与多选分布 | 显示该题有效答题人数；多选各选项占比可合计超过 100%，需提示 |
| 评分分布与均分 | 以该题有效评分为分母，未答不计为 0 分，保留量表范围 |
| 部门对比 | 使用同一版本与统计口径；匿名小样本按已确认策略处理 |

例如指定 80 人、有效提交 60 人，回收率为 75%；不能用总部 621 人作为该任务分母。催答只提醒有资格且未提交人员，遵守班次窗口与发送冷却，任务关闭后停止提醒。

Excel/CSV 导出应包含任务、版本、用途、统计期间、当前筛选范围及统计口径。实名可导出授权范围内答卷与未填名单；匿名参与状态和匿名答案使用分开的导出，不能通过相同记录标识或精准时间拼接回身份。

## 3 钉钉扫码与公共接入流程

### 3.1 身份识别与业务授权

钉钉内 H5 入口：扫一扫或任务链接 → 打开 H5 → 通过已配置应用取得并校验身份 → 按 CorpId 与 userid 映射组织成员 → 建立或复用本系统会话 → 校验总部、任务、时间和参与资格 → 填写或本人签到。

当前已有钉钉 OAuth 登录与绑定基础，不等于已完成钉钉内 H5 免登。实施时先核对现有应用、权限与接入，再选择合适的身份链路；免登相关授权码与当前 OAuth 回调是否兼容须按实际接口确认，不能直接混用。应用配置和服务端身份处理可参考[钉钉官方 H5 免登示例](https://github.com/open-dingtalk/h5app-auth-demo)。

二维码中只放任务入口与受控访问凭证，不携带姓名、手机号或可作为身份凭据的员工 ID。本人身份来自验证后的服务端会话，不能信任 URL 中的 userid、部门或角色。登录前保留内部任务返回路径，登录后继续原任务。

普通手机浏览器或系统相机打开链接时，不能默认存在钉钉容器能力，应走现有可用登录方式并返回任务。PC 人事系统中的入口继续复用现有接入，宿主显示页面不代表已完成账号会话共享。

### 3.2 共用能力与各业务差异

| 共用能力 | 问卷或评价 | 签到 |
| --- | --- | --- |
| 身份与总部准入 | 判断谁能填写，匿名答案与参与身份分离 | 必须记录本人有效签到 |
| 二维码和返回路径 | 指向具体发放任务及固定版本 | 指向具体线下场次与签到窗口 |
| 资格校验 | 受邀名单或总部内部自由填写范围 | 当场应到名单及补签授权 |
| 时间与重复处理 | 开放、截止、一人一份正式答卷 | 时间窗口与一场次一员工唯一签到 |
| 回收及记录 | 答卷、提交状态与导出 | 实到、未签到、迟到、请假、缺勤与补签审计 |

共用登录、账号映射、二维码生成与消息框架，各业务保持自己的资格和记录。问卷二维码可在任务开放期间使用；签到按场次窗口和凭证有效期校验，不机械套用相同失效时长。

钉钉扫一扫或系统相机读取二维码不要求自建 H5 内相机扫码。局域网 IP 可用于同网测试，手机使用蜂窝网络时不能直接访问电脑的内网地址；正式入口需核对稳定访问地址与钉钉应用配置。若增加 H5 页面内相机扫描，再按 [MDN getUserMedia](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia) 核对 HTTPS 与真机兼容。

原人工考勤写入链路接收客户端学员 ID，接入扫码前先核对本人或授权教师的写入资格，不能只加二维码页面。源码核对位置：[考勤路由](../../apps/api/src/routes/course/attendance.ts)、[考勤服务](../../apps/api/src/services/attendance/attendance.ts)。

## 4 导师带教的业务设计

### 4.1 关系与职责

师徒关系包含学员、导师、计划、有效期和当前状态。建议同一带教计划在同一时点明确一名主导师；是否支持辅助导师待制度确认。导师候选资格按公司制度维护，不把钉钉管理员、课程讲师或职位名称直接转换为导师权限。

| 角色 | 职责与范围 |
| --- | --- |
| 培训岗 | 批量绑定、选择任务模板、下发计划，查看全局进度和异常，处理换导师与任务调整 |
| 学员 | 查看本人导师和任务，学习、考试、确认现场实操或提交材料，查看点评及补充要求 |
| 导师 | 仅查看有效关系下的任务，记录辅导、核验实操、点评、评分、退回或认证 |
| 主管 | 查看授权部门带教状态；仅在被配置为复核人时处理对应任务 |

运营部五位平行主管使用显式部门或人员范围及复核人配置，不自动寻找职位层级上的“上级”。查看部门状态不自动获得所有任务的改分或认证权限。

### 4.2 任务类型与发布

| 类型 | 完成证据 | 结果处理 |
| --- | --- | --- |
| 课程学习 | 引用现有有效学习记录、进度与内容版本 | 不复制另一套学习百分比 |
| 在线考试 | 引用现有答卷、正式成绩与合格结果 | 不复制或覆盖原考试成绩 |
| 口头问答或现场实操 | 学员完成确认，导师记录观察结果；按任务要求选填说明或附件 | 学员自报完成后仍需核验 |
| 材料作业 | 按要求提交文本、图片、音视频或文档 | 保留提交轮次、点评及退回历史 |

任务模板固定目标、可观察的评分标准、截止规则、附件要求、评审步骤、分值及认证条件。按需分组和设置相对入职日的截止时间，支持简单带教安排；一期不因此追加完整岗位学习地图编辑器。

建议认证依据同时展示必修课程、必要考试与实操评审是否满足。评分合格和最终认证分别记录；自动判定课程或考试型任务可以复用已有结果，最终带教认证按发布时规则执行。

### 4.3 提交与点评流程

绑定师徒 → 下发固定版本任务 → 学员学习或实操 → 提交完成说明或材料 → 导师核验、点评及评分 → 通过或退回补充 → 按配置进行主管复核 → 认证 → 培训档案与报表。

任务过程状态建议为待完成、待点评、退回补充、待复核、已完成、已取消。评分是否合格与最终认证另列；逾期也是独立时间标记。点评待办不应覆盖已经完成的学习进度，考试通过也不自动替代实操认证。

退回需写明补充要求；每次重提交保留原内容、提交人、时间、评分与点评。主管复核的适用任务、退回到导师还是学员及认证责任人，在发布前确定。100 分制、60 分及格只作为可编辑示例。

现场核验应支持导师直接记录观察结果及核验时间，不要求学员为了提交而制作无业务价值的视频。若任务确需附件，明确类型、大小、访问权限和保存期限；不得公开其他学员作业或敏感业务素材。

### 4.4 持续提醒与交接

系统分别提醒未完成学员、待点评导师及待复核主管。建议报表区分“学员未完成”与“导师处理滞后”，避免把待审批误算为学员未学。提醒遵守客服早晚班窗口、发送频率和去重；钉钉投递失败可查可重试，不将站内记录创建当作外部通知送达。

调岗、离职、导师停用或更换时，停止不适用的新提醒并进入异常队列。更换导师保留旧关系、已评结果和未完任务，记录交接人、接收人及原因，不重置全部学习与考试历史。

导师辅导凭证和徒弟评价导师属于授客产品参考。是否采用、是否匿名及管理人员可见范围需另行确认；一期核心带教验收不以双向评价为前置条件。

## 5 现有系统复用与页面补充

| 能力 | 复用现有 | 需要新增或完善 |
| --- | --- | --- |
| 问卷与评价 | 企业成员、范围校验、固定满意度评价经验、消息框架 | 模板版本、发放任务、参与记录、草稿答卷、分题统计与各类导出 |
| 钉钉扫码 | OAuth、账号绑定、组织同步与现有 H5 路由 | 钉钉内身份链路核对、扫码回跳、任务资格与真实二维码 |
| 签到 | 课程与人工考勤结构 | 场次、应到名单、本人授权、窗口、去重、补签及缺勤统计 |
| 导师带教 | 培训计划、课程、考试、学习档案、授权与消息框架 | 师徒关系、带教任务、提交轮次、点评、复核、认证及交接历史 |
| 督办与报告 | 现有提醒记录与作业队列框架 | 周期任务、真实消息投递结果、导师待办和主管定期报告 |

业务关联使用现有组织成员、计划、课程与答卷主键；问卷和带教需要各自完整记录，不只把数据塞进旧满意度或人工评分字段。发布名单、任务版本、评审记录与消息执行结果可追溯。已有计划引擎统一处理人员和期限，带教扩展不再建立一套重复派课及成绩系统。

建议补齐的页面流程：

- 管理端问卷：模板编辑与预览、发放对象和匿名设置、名单核对、二维码和链接、回收统计及未填提醒。
- 学员 H5：独立需求调研与课后评价填写，显示资格、匿名说明、草稿、提交回执和关闭状态。
- 管理端带教：批量绑定及异常处理、模板与评分标准、评审步骤、学员进度、导师滞后与认证明细。
- 导师端：待点评、待补充与已处理任务，查看提交历史并记录现场核验；主管端按配置增加待复核入口。

现有[问卷稿](../../prototypes/zz-training-phase-one-20261012/survey.html)、[带教管理稿](../../prototypes/zz-training-phase-one-20261012/mentoring.html)、[导师稿](../../prototypes/zz-training-phase-one-20261012/mentor.html)和[学员带教稿](../../prototypes/zz-training-phase-one-20261012/learner-mentoring.html)是基础评审入口。上述详细设置尚需在实施前补充到对应交互，不把现有模拟点击当作全部流程已设计完毕。

## 7 制度确认与推进顺序

| 待确认项 | 需要确定的具体内容 | 对实现的影响 |
| --- | --- | --- |
| 问卷身份与改答 | 哪些需求调研或评价采用匿名，是否允许提交后修改，小样本展示规则 | 决定答卷存储、导出和统计方式 |
| 评价资格 | 是否要求参加对应场次、签到或完成课程 | 决定扫码后的资格检查 |
| 导师制度 | 候选资格、同计划主导师数量、任务评分标准、最终认证责任人 | 决定绑定与评审配置 |
| 主管复核配置 | 已确认按任务决定是否复核；配置适用任务、五位平行主管各自范围、退回对象及代办规则 | 落实已确认的评审步骤和服务端权限 |
| 提醒与报告 | 班次窗口、每日频率、点评期限、报告周期及发送时间 | 周报可作为配置选项，定期报告不延期到二期 |
| 接入 | 现有钉钉应用、可用权限、H5 入口地址、真实 HR 登录及返回方式 | 决定免登和扫码的真实联调路径 |

沿主方案分批推进：先完成总部与账号权限基础；再补问卷及带教详细交互、发布规则和数据模型；实现问卷、签到与带教闭环后接入持续提醒、真实钉钉通知与主管报告。每批均通过对应负向权限和真机用例，不能等待全部页面做好后才核对身份接口。

建议本会话作为一期需求与实施主线，统一维护本目录、对应设计稿及代码提交。其他会话的资料分析附来源后合入；同一模块由一个执行会话负责修改与验证，避免两份需求口径或相互覆盖的代码。
