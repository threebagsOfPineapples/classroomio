## 2. 已确认需求

1. 范围为总部，提需时 621 人、19 个部门；集团约 1,000 人后续再议。人数随合法入离职变化，报表标记统计时点。
2. 内部自建、自研，复用当前 `zz-train`，不采购 SaaS。
3. 一期围绕谁学了、谁没学、进度、考试结果；培训过程有证据，后台能批量处理，持续提醒减少人工催学。
4. 钉钉账号登录、组织同步、新人自动派课属于一期。旧仓库文档中的“钉钉/人员导入暂缓”不再作为此次范围排除依据。
5. 学员端改为手机版 H5，覆盖 iOS、Android；PC 管理与查看保留。原微信小程序要求被本次用户决定替代。
6. 嵌入现有自建人事系统，按现有对接推进；不臆造系统名称、宿主域、技术栈、已接通的会话共享机制。
7. 课程从空库启动，逐步上传和沉淀；客服双班支持 3–5 分钟微课。
8. 一期包含题目编辑、组卷、在线考试、客观题自动判分、基本防切屏/退出、首次学习防向前拖拽；不做人脸强校验。
9. 定向需求调研、课后扫码评价、线下二维码签到、缺勤统计、导师带教均属于一期，不移入二期。
10. 培训岗看全局、主管看本部门、员工看自己；老板看汇总，导师按带教关系处理任务。未提供的完整权限表以草案待业务确认。
11. 学习、考试、问卷、签到、带教需导出 Excel/CSV；操作范围和数据范围一致。
12. AI 做课、陪练、测评本期不做；HR/薪酬/绩效业务打通本期不做。学习地图、积分证书体系深化、知识圈、讲师运营深化等按原分期推进。

## 4. 核心业务口径

### 4.1 人员范围与组织

总部准入以组织和部门 ID 白名单、在职状态及实际名单为依据。621 人/19 部门是提需时基准；每次同步先预览差异，再确认，不为了凑人数删除员工。仓库历史资料提到集团目录 931 人、286 部门，是其他时点的读取记录，本次未调用公司通讯录，不能当当前事实。

员工主键沿用组织成员 ID；外部账号按 CorpId + userid 绑定，姓名不能作为账号合并依据。多部门保留关联，明确主部门；岗位文本做映射，工种与班次单独维护，不能从部门名称猜出。停用/离职停止新派课和提醒，既有学习、考试及带教历史保留。

客服一/二/四部 84+ 人、剪辑 105 人、主播 80 人、货架电商 21 人、运营 191 人是不同业务维度，不能简单相加当总部总人数。货架电商独立显示，不能因无 BP 漏入范围。内训师候选池限业务确认的组长、主管；导师候选资格独立按制度维护。

### 4.2 学习、考核、带教独立记录

| 维度 | 状态与字段 | 判定原则 |
| --- | --- | --- |
| 任务资格 | 已分配、取消、停用；内容版本与截止时间 | 有应学任务才进入未学名单；未分配不算未学 |
| 学习 | 未开始、学习中、已学完；进度、有效时长、最近学习、断点 | 未开始需无有效学习证据；完成按课程版本要求判定 |
| 时间 | 未开始窗口、在期限内、已逾期 | 逾期是时间维度，不能覆盖已学进度或考试结果 |
| 考试 | 未参加、进行中、待评分、已出分；合格/不合格 | 未参加/待评分不写为 0 分；客观题服务端判分 |
| 带教 | 待提交、待点评、退回、已认证；点评、评分、证据 | 学完或考试通过不自动替导师认证 |
| 计划结业 | 待满足、通过、不通过 | 按发布时的必修、考试和带教条件组合；不覆盖各域原始结果 |

学习进度建议按该版本必修课时的完成比例聚合；有效视频时长、有效阅读与考试成绩分别显示。继续学习按服务端返回的未完成课时和断点进入，不把“最近打开页面”当最近有效学习。复习已完成内容不重写首次完成时间。单门课程跨多个计划复用历史进度是否允许，需在派课时明确策略并留痕。

视频首次学习采用限前拖策略；允许回看已学内容，达到课程完成要求后可复习。累计有效时长不因直接拖到末尾增加；暂停、失焦/切后台、断网和重复心跳要分别验证。外部链接、无法可靠追踪的格式要提示并设人工核验流程，不能默认为自动学完。

### 4.3 指标分母

| 指标 | 建议公式 | 必须同时展示 |
| --- | --- | --- |
| 总部任务覆盖率 | 期间获得有效任务的总部员工去重人数 / 同期总部应覆盖在职人数 | 统计期间、人员范围、分子/分母 |
| 学习参与率 | 已产生有效学习的应学人员 / 已分配人员 | 参加与未开始人数 |
| 学习完成率 | 完成规定课程的人员 / 应学人员 | 已学完与未完成，不等同结业 |
| 考试参加率 | 已交卷人员 / 应考人员 | 缺考、进行中、待评分分别列出 |
| 考试合格率 | 正式合格人员 / 已发布正式分人员 | 未考、待评分不混入分母；另提供“应考达标率” |
| 应考达标率 | 正式合格人员 / 应考人员 | 用于未达标名单，包含缺考但保留原因 |
| 带教认证率 | 已认证人员 / 应认证人员 | 待提交、待点评、退回分布 |
| 签到率 | 已有效签到人数 / 当场应到人数 | 经批准请假单列；未结束称未签到，结束后计缺勤 |
| 问卷回收率 | 已提交人数 / 有效受邀人数 | 有效/无效、实名/匿名回收方式 |

跨课程和跨计划报表同时支持“去重人数”和“任务人次”，每个数字明确单位。组织变更后的当前可见范围和历史部门快照分别处理，报表不得因员工调部门而静默改写历史。

## 5. 一期功能方案

### 5.1 培训岗和主管 PC

工作台首先呈现需要跟进的事项，主流程为“发现未学/滞后 → 核对人员 → 催学 → 查看执行结果”。学习追踪台账按部门、岗位、工种、课程、计划、状态、日期筛选，字段至少包括员工、工号、部门、岗位、工种、进度%、最近学习、有效时长、考试分、考核合格与否、导师认证、截止日期和最近提醒。个人详情进入逐课时证据、考试答卷与带教记录。

批量选人提供当前页和全部筛选结果的明确区别。催学确认显示实际可提醒人数及跳过原因；导出未学/未达标名单直接沿用当前筛选。部门主管入口固定为已授权部门，筛选不能扩大权限。

建课流程为基本信息、上传内容、学习要求、可见范围、预览、发布；空库只需保存草稿，不要求预置课程。批量上传逐项报告结果，转码/解析未完成不能发给学员。课程管理员预览不产生真实学习和答卷。

计划流程为基本信息、课程与考核、人员匹配、导师与提醒、发布核对。发布固定内容与应学名单快照，后续增补人员或变更版本有独立操作和审计。客服早晚班提醒分别设置可打扰窗口，微课时长和下一步任务在手机首页可见。

### 5.2 考试

题库编辑、题目复用、组卷、预览与发布使用现有引擎扩展。试卷固定题目版本、分值、答案和判分规则；设置窗口、时长、及格线、机会次数、重考与成绩发布方式。已开考后修改草稿不影响现有答卷；主观题未评完保留待评分。

基础防作弊采用记录和规则处置：离开页面事件记录时间、次数、设备会话；提醒阈值/自动交卷阈值在考前公示，并允许人工核查。退出保留草稿且继续计时；是否还能进入以服务端时限和机会为准。重复交卷去重，手机来电、正常短暂切换等异常不直接等同作弊。浏览器事件能力说明见 [MDN Page Visibility](https://developer.mozilla.org/en-US/docs/Web/API/Page_Visibility_API)；浏览器能力不能保证彻底禁止用户关闭窗口，验收应检查事件记录、时限和再次进入处理。

补考针对本人或批量缺考/未通过人员，保留原答卷与原分数、授权原因和操作者，不直接覆盖历史结果。考试通过和带教通过不替代课程学习完成。

### 5.3 独立问卷与评价

问卷模板与问卷发放分开。模板包含单选、多选、评分、文本和必答项；发放绑定部门/人员、截止时间或课程/场次，固定版本和受邀名单。培训需求调研可独立于课程存在，课后评价可按线下场次开放，不受旧“必须培训结业”条件限制。

实名与匿名在发放前确定。匿名方案使用独立参与记录做回收与催答，答案不向管理人员提供按员工反查；匿名小样本汇总策略另行确认。二维码仅提供发放入口，访问后仍验证发放对象与有效期。提交去重，未提交、已提交、已关闭、无资格和加载失败分别显示。

### 5.4 线下签到

场次包括计划/课程、讲师、时间地点、应到名单、签到窗口与请假/补签策略。二维码指向场次签到入口，短期 token 与窗口有效；员工登录后取本人身份，服务端验证对象、资格、时间和重复记录，不接受任意员工 ID 替签。

未登录扫码先登录再返回原场次。过期、无资格、已签到分别反馈；管理员补签需原因及审计。签到期间展示未签到人数，关闭后再核算迟到、请假和缺勤，并导出应到、实到及明细。

手机版 H5 一期可通过钉钉扫一扫或手机系统相机打开签到/评价链接，不依赖自建页面内相机扫码。在普通 LAN HTTP 页面内申请相机存在安全上下文限制，若后续加入页面内扫码需 HTTPS 与真机验证，依据 [MDN getUserMedia](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia)。LAN IP 可用于同网访问验证，不应把当前未启动服务或页面占位二维码当真机签到验收。

### 5.5 导师带教

建立师徒关系和有效期；每个任务有学员、导师、所属计划、要求、截止、证据、提交、点评、评分及认证版本。课程/考试型任务引用现有结果；实操型任务由学员提交说明/材料，导师点评或退回补充，评分与认证分开记录。

导师只看到本人有效关系的学员和任务。更换导师保留原记录与任务交接；停用导师进入异常队列。学员未完成由系统持续提醒，导师未点评由系统提醒导师；主管看到本部门带教状态，培训岗可以批量分配和处理异常。是否需要“导师初评 + 主管复核”作为可配置步骤待制度确认，不能默认把学员自行勾选当认证。

### 5.6 钉钉新人派课、持续提醒和主管报告

复用已有钉钉 CorpId/userid、OAuth 登录、账号绑定和目录同步。现有登录是 OAuth 跳转与状态校验，不宣称已具备钉钉内 H5 免登。按实际应用权限和现有接入选择可用事件方式，授权后联调。

事件处理顺序：验证事件来源 → 去重 → 限定总部准入 → 更新组织资料 → 匹配部门且岗位/工种 → 创建有效任务 → 关联导师 → 写消息待发送记录。不同规则可明确选择并集，但单条“部门内岗位”规则默认交集。岗位缺失、身份冲突、无导师或资源未发布进入待处理队列；不能因此派给全员或静默跳过。

同一员工、规则版本、目标任务只下发一次，重复事件和补偿同步不重复派课；对账补偿用于事件漏收。已有学习与历史权限保留，钉钉管理员身份不自动转换为培训管理权限。

消息以站内为可查询基础，钉钉工作通知作外部投递。单条消息记录待发送、发送成功、失败、重试及站内已读；“站内记录已创建”不能写成“钉钉已送达”。现有 24 小时冷却作为基础，每日频率、班次窗口、合并提醒和失败重试规则可配置。完成、取消、离职、停用及规则关闭时停止新提醒。

主管定时报告只包含其授权部门，报告时点固定，提供完成/未学/不合格摘要和需跟进名单。多个平行主管按各自显式授权范围执行，不按职位名称猜测。

## 6. 权限草案与接入边界

原始完整角色表没有提供。以下为本次方案草案，不代表已授权现有员工；主管建课/派课、老板人员明细和导师复核权限需确认。

| 角色 | 默认数据范围 | 建议动作 | 明确限制 |
| --- | --- | --- | --- |
| 培训岗 | 总部全部 | 课程、计划、考试、问卷、签到、带教、督学、报表 | 不跨企业；角色授予单独授权 |
| 部门主管 | 明确授权本部门，可多部门 | 查看、督学、导出本部门；建课/派课可另授权 | 不默认包含全部子部门或其他同层主管范围 |
| 员工 | 本人及其有效任务 | 学习、考试、签到、评价、提交实操 | 不通过修改 ID 查看别人或替签 |
| 导师 | 有效师徒关系及相应任务 | 点评、评分、认证、查看必要进度 | 不自动拥有全部门档案权限 |
| 讲师 | 获授权课程/考试/场次 | 内容维护、批改、现场管理 | 候选为组长/主管；不等同导师 |
| 老板 | 总部汇总只读 | 大盘与部门对比 | 默认不提供人员明细和业务写入，按需要显式授权 |
| 系统管理员 | 技术配置与显式授予范围 | 接入、运行、角色配置 | 不以技术角色默认为所有成绩修改权限 |

后端统一校验身份、组织、动作、范围和资源归属。列表、详情、统计、下载、导出、签到、消息和任务作业都用相同谓词；前端菜单与角色预览不是安全措施。并行主管范围使用成员×部门授权关系，不再只依赖部门唯一负责人字段。

培训动作逐次审计至少覆盖导入/同步、授权变更、派课与撤销、考试发布/调分/补考、签到补签、带教认证、提醒与导出。记录操作者、动作、对象、时间、范围、结果、必要原因及请求标识；不将密钥或完整答卷写进普通日志。

人事系统按现有实际方式嵌入与返回，不另起账号系统。先核对宿主地址、登录链路、外部账号映射、iframe 策略、cookie、移动返回链接及退出行为。代码目前仅找到 `frame-ancestors` 扩展与 host-only 会话，未找到 HR 会话交换完整证明；不能把增加 iframe 白名单当 SSO 已接通。现有机制可用则复用，缺失时再在原有接口上补会话接入方案。接口明确版本和权限，后续提供学习结果数据回流，HR/薪酬/绩效计算不在一期。

## 7. 界面与交互规范

沿用现有 `apps/dashboard/src/training.css`：白色侧栏、浅灰底、至臻橙 `#E85A0C`、深橙主按钮 `#B8460A`、正文 `#1A1A1A`、边界 `#E0E0E0`、选中底 `#FFF4EB`。中文系统字体不依赖外网。管理界面以筛选与台账为中心，学员首页突出下一步任务；沿用现有课程编辑和组件结构。

PC 页面结构：侧栏约 212–224 px → 组织/角色顶栏 → 标题与主操作 → 筛选和状态 → 批量操作 → 表格与明细。学习追踪作为高频入口；培训岗主导航按日常跟进、培训组织、组织设置分组。主管仅保留本部门工作台、台账和报表；老板是汇总视角，导师是本人任务队列。

手机 H5 页面结构：简洁顶栏 → 下一步任务 → 课程/考试/认证独立状态 → 待办 → 学习、考试、签到、我的底部导航。微课直接显示时长、断点、截止时间；考试提醒和导师退回任务优先于可选课程。手机无桌面表格压缩成的学习主页。

空库/未派课引导具体下一步；真实零显示 0，未知显示“—”，请求失败提供重试，不伪装为 0。无访问资格明确提示返回本人/授权范围。普通确认弹窗不因遮罩或 Esc 丢弃内容，主操作只有一个；取消与关闭明确。加载与失败时禁止基于不确定名单发送批量提醒。

界面设计稿支持明暗、空数据/空库、请求失败、权限不足四种演示状态。正式页面文案沿用项目翻译键；有复杂表单的实施继续使用 `Page.SettingsActions` 与未保存提醒，不把本地 HTML 文案直接粘到生产组件。

## 8. 技术落点与数据方案

保持现有 SvelteKit + API + PostgreSQL + Redis/作业队列 + 对象存储，PC 与 H5 共用服务端权限及业务接口。复用 `/admin/*`、`/learn/*`、课程学习及企业 API，不为 H5 建另一套成绩和进度存储。

新增实体建议如下。此为设计，不是已执行迁移；实施前核对已有表和迁移最大时间戳，同一 PR 按仓库约定合成一个迁移。

| 实体 | 关键关联与字段 | 唯一/边界原则 |
| --- | --- | --- |
| 员工分类/班次与总部范围 | organizationmember、部门来源 ID、岗位映射、工种/班次字典 | 不覆盖现有工号/权限；总部范围独立于通讯录授权范围 |
| 部门授权 | 企业成员、部门、动作权限或角色、有效期 | 支持平行主管和多部门，不默认递归扩权 |
| 学习任务/台账关联 | 现有 enrollment、course、员工、内容版本、分配来源、截止 | 同规则目标去重；百分比从有效证据计算，可重建缓存 |
| 问卷版本与发放 | 模板、版本、发放、对象、参与记录、答卷 | 一发放一员工唯一参与；匿名答案与身份记录分离 |
| 场次与签到 | 场次、应到成员、窗口、token 摘要、签到、补签原因 | 一场次一成员唯一；身份来自会话 |
| 师徒关系与带教任务 | 导师/学员成员、有效期、任务、提交、点评、评分、认证 | 历史关系/点评保留；不得只在 JSON 存成员关联 ID |
| 派课规则与事件记录 | 规则版本、关系型条件、来源事件、匹配/执行结果 | 事件去重与目标去重；失败可重试 |
| 消息与报告作业 | 学员/主管、来源任务、渠道、状态、发送/读取时间 | 冷却、班次、失败重试独立；按授权范围生成 |
| 业务操作审计与导出记录 | 操作者、组织、动作、实体、时间、结果、原因、范围快照 | 逐次追加；不由“最近操作人”字段替代历史 |

拟定接口族：

| 接口族 | 复用/扩展方向 |
| --- | --- |
| `/enterprise/employees` 与目录同步 | 总部白名单、完整批量预览/确认、岗位工种筛选 |
| `/enterprise/plans` 与个人培训 | 目标交集、发布快照、台账查询、当前筛选提醒/导出 |
| 考试现有接口 | 异常事件、服务端截止/草稿/交卷、题库运营及补考 |

| `/enterprise/reports` 与审计 | 同范围统计/导出、主管报告、大盘及操作记录 |

## 9. 一期内部交付批次

以下全部属于一期。分批减少同时联调的风险，不把导师、问卷或签到默默移到二期；日历排期待开发人力与接口资料核对后确定。

| 批次 | 交付内容 | 进入下一批的验收门槛 |
| --- | --- | --- |
| A 基础与范围 | 环境启动、总部名单/岗位工种、账号对接核对、明确部门授权、原签到越权修补 | 空库可启动；导入预览不扩大总部范围；跨部门/替签负向验证 |
| B 追踪与考试 | 统一学习台账、PC/H5 任务、微课/文档、有效时长/续学、防前拖、题库组卷/判分、未学/未达标导出 | 一门真实课程完成“派课→学习→考试→台账→导出”；结果各维度独立 |
| C 现场与带教 | 定向问卷、扫码评价、线下签到、师徒/实操点评认证、相应导出 | 真机扫码、重复/过期/无资格；导师只能处理本人任务 |
| D 自动运行与管理视角 | 新人事件派课、周期催学、钉钉投递/重试、主管报告、老板大盘、人事嵌入复核 | 无人工分配的新人闭环；消息结果可查；主管报告无跨范围数据 |
| E 总部上线验收 | 权限审计、621 人口径数据校验、性能、手机兼容、备份恢复、培训岗独立操作 | 所有一期验收项通过，真实环境记录与待办交接清楚 |

业务人员负责核对总部目录、课程内容/答案、导师制度与通知窗口；数智团队负责环境、接口、实现和验收证据。培训岗能在正常后台完成业务操作；技术运维、备份和故障处理仍有团队责任人，不把“低运维”解释成培训岗独自维护服务器。

| A05 | 编辑题目组卷、发布、答题、交卷与判分 | 服务端评分、试卷版本固定、重复交卷去重、待评单列；考试窗口/次数/补考生效 |
| A06 | 手机考试切换应用、退出、刷新、超过截止 | 异常可查，规则提示明确，草稿及服务端时限正确；不以浏览器演示替代真机 |
| A07 | 导出未学/未达标完整筛选名单 | Excel 可直接打开；人数与列表一致；主管导出不含范围外员工；超过单页仍完整 |
| A08 | 在学习台账批量催学与重复点击 | 实际收件范围正确、已完成等跳过、冷却去重、站内与钉钉状态分开 |
| A09 | 用总部新人入职事件触发课程下发，不进行人工分配 | 按部门且岗位匹配，重复事件不重复派课；非总部、缺岗位、无导师有明确结果 |
| A10 | 保持新人未完成，运行周期提醒与主管报告 | 频率/班次窗口生效，完成/离职后停止；报告只含主管授权范围，失败可重试 |
| A11 | 绑定师徒、下发实操、提交、点评、评分、退回及认证 | 全部记录可见可导出；更换导师保留历史；无权限导师直接 API 操作被拒绝 |
| A12 | 向指定部门/人员发布需求问卷并回收 | 定向资格、版本、重复提交、截止生效；匿名答案无法按员工反查 |
| A13 | 真机扫描签到/评价二维码，未登录/重复/过期/无资格 | 登录后回原场次；本人签到唯一；关闭后缺勤/请假正确；员工不能替别人签到 |
| A14 | 导出学习、考试、问卷、签到、带教五类数据 | 字段、筛选、统计时点、权限和在线明细一致，操作可审计 |
| A15 | 培训岗、两个平行主管、员工、导师、老板直接访问列表/详情/统计/API/导出 | 各范围一致；跨组织、跨部门、他人身份和篡改 ID 被拒绝，老板默认只读 |
| A16 | 老板看总部大盘，选择时间与部门 | 覆盖/完成/合格口径明确，分子分母一致，人数不与人次混淆 |
| A17 | 在现有人事系统及钉钉入口登录进入 PC/H5 | 账号映射、回跳、嵌入、续学、扫码后返回和退出按现有接入真机/真实宿主验证 |
| A18 | 批量导入、学习高峰、考试交卷与同时导出 | 根据已确认负载方案记录响应、错误率和恢复结果，不以机器 RAM 或一次健康检查断言 621 人不卡顿 |
| A19 | 培训岗独立建课、派课、出卷、问卷、签到、绑定导师、督学与导出 | 标准操作无需改 SQL/脚本；异常队列有处理说明，技术运维责任明确 |
| A20 | 回归已有课程、权限、阅读观看、判分、补考、档案与已有证书行为 | 不丢历史数据、不改变既有结果；界面文案使用翻译键，语言占位符一致 |

性能建议作为待确认的量化目标：核心台账/汇总接口 P95 ≤ 2 秒、PC 看板主要内容 ≤ 3 秒；测试至少覆盖 100 人持续学习与批量导出并行，以及 621 人在集中考试场景下创建答卷/交卷的峰值。并发量、媒体码率、终端网络及目标硬件须先明确；目标未经本次实测。视频并发带宽单独测，不把 API 秒级代表视频播放流畅。重要计划的备份恢复、重复事件补偿和升级回退需在上线前演练。
