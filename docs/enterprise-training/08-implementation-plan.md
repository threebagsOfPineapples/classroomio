# Phase 1–10 实施计划与验收门槛

Phase 0 完成静态审计与设计文档；尚未进入业务编码。每进入下一 Phase，都先核对相关旧代码/调用者，写该阶段细化实施清单，生成并审查兼容 migration，完成后端、前端与关键测试，再跑匹配范围的测试、lint、typecheck、build。仓库 `AGENTS.md` 对一个 PR 的 migration 数量、提交前格式检查和构建另有明确规则。每阶段采用独立可回顾提交；发布/部署与代码完成分别验收。

| 阶段 | 最小实现与复用 | 关键验证/出口 |
| --- | --- | --- |
| **1 企业组织** | 新增 department 树与组织成员企业属性；沿 `organizationmember`、audience、Better Auth 建员工列表/编辑；企业角色及 API 范围校验；部门负责人只读本部门及子部门。 | 部门不能跨企业/成环；工号唯一；离职不可分配；本人/部门/讲师/管理员及跨企业读写权限测试。 |
| **2 课程体系** | 扩展现有 Course/Section/Lesson；优先复用 tag 分类、logo/banner、发布开关、Lesson 视频/文档/文本和讲师关联；补企业课程筛选、必修标识及学时字段。 | 旧课程可读；课程发布与内部自选可见性正确；课程/章节/课时权限与移动布局检查。 |
| **3 培训计划** | 新建 Plan/Target/PlanCourse/Enrollment；保留 Cohort 作为可选班次。按部门/子部门、岗位、指定员工解析预览名单，发布时物化任务，并沿用课程组员分配链。 | 重复目标去重、变更岗位后快照稳定、重复发布幂等、事务失败恢复、跨企业课程拒绝。 |
| **4 员工学习** | 在 `/learn` 复用 `/lms` 课程卡/学习进度与 Cohort 目标；我的培训、详情、继续学习、待考试、证书。 | 员工只见本人任务；课时完成和计划聚合一致；缺少学时/分数显示待更新，不显示伪零。 |
| **5 考试作业** | 扩展 Exercise/Question/Submission，保留现有题型与客观题自动评分/人工批改；加考试时间窗、时长、次数、补考和答案显示策略。共享题库仅在现有题目归属允许时设计复制/版本方案。 | 时间窗/到时交卷、重复提交、次数、缺答、客观题及简答人工评分、学员访问隔离测试。 |
| **6 综合评分** | 新建 Scheme/Item/Score/Detail/Adjustment；取有效提交、讲师分、出勤与进度，保留来源，人工调分仅追加。 | 权重总和非 100 禁发布；缺项 PENDING；0/满分、89.9 示例、通过线边界、调整前后和重复计算幂等测试。 |
| **7 培训评价** | 独立评价表与学员评价页；课程、讲师、实用度、满意度 1–5，文字反馈；统计只消费评价表。 | 只对本人已完成培训评价；评分范围、重复评价、匿名策略与成绩完全隔离。 |
| **8 培训档案** | 从 Enrollment/Score/课程源进度/证书聚合长期记录，提供员工本人和授权管理者视图；Matrix 显示未开始/进行中/完成/过期/失败。 | 档案可追溯到每条培训任务；补训周期/证书到期；跨部门/跨组织读取隔离与查询性能。 |
| **9 Dashboard** | 复用现有 analytics/chart；工作台、部门和员工统计、成绩与满意度，统一时间窗口和分母。 | 小样本手工对账；缺值与 0 分开；筛选权限和导出一致；大样本查询性能。 |
| **10 AI 扩展** | 复用 `packages/ai-assistant` 多提供商模型与现有 Builder/Tutor；AI 评分先只存建议、维度/置信度与审核结论，之后再评估出题/计划建议。 | 无密钥可降级；模型响应校验；讲师审核前不写最终分；输入权限和敏感数据审查。 |

## 每阶段执行顺序

源码和旧数据基线 → 复用/扩展/新增决策 → 阶段设计与 API/页面清单 → Drizzle schema + migration（遵守一 PR 一文件） → 查询/服务/API 权限 → SvelteKit 页面 → 关键测试 → lint/typecheck/build → 测试库迁移与功能验收。Phase 6 和权限/发布链必须有可运行的回归测试；单纯文档阶段不需要虚构业务测试结果。

## 跨阶段验收案例

在隔离环境用一个企业、直播运营部和员工张三创建“2026 Q4 直播运营能力提升计划”，关联直播间数据分析、主播话术、商品排品、AI 直播复盘，部门目标发布后确认恰好生成一条张三 Enrollment 和四课程访问；完成学习、考试 92、作业 85、讲师 88、进度 100，40/30/20/10 方案得 89.9、PASS；张三提交 5/4/5/5 评价，档案、Matrix 与部门 Dashboard 显示同一任务结果。业务验收须经过真实 API/数据库/页面，不能用单元测试代替。

## 风险清单与处理顺序

1. **模型重叠**：Cohort 目标分配、Course 合规完成记录与新 Plan Enrollment 容易重复。先定义单一写入责任与同步事件，旧班级不强制迁计划。
2. **身份/租户**：全局 user、profile 与多组织成员不等价；员工属性、角色、外部 ID 均须在企业作用域，跨租户资源关联是最高优先级拒绝项。
3. **历史兼容**：旧 Program、课程发布状态、提交/证书多套记录并存；新结果只从可追溯来源产生，不把旧分数自动解释为培训合格。
4. **评分可靠性**：不同题型满分、重考取分、缺项、权重与人工调分需要冻结规则版本和明细；选定补考/舍入政策后测试，不在 UI 中临时计算。
5. **发布并发与组织变动**：名单预览和发布间可能调岗；发布时事务内重新解析并保存快照，报告与预览差异，重复请求依唯一约束幂等。
6. **进度与统计口径**：视频、课时、练习、合规周期各有不同完成语义；学时不能由课程标称时长直接充作真实学习时长，无法计量时显示未就绪。
7. **迁移高水位与锁**：Drizzle journal `when` 需高于主干；旧库、大表索引和回填先在副本验证，避免生产长锁/静默漏跑。
8. **已有商业/公开界面**：课程价格、支付、公开目录仍在代码；内部入口需隐藏/禁用购买动作，但旧公开站功能与数据先保留。
9. **许可证与品牌**：根 LICENSE 为 AGPL 文本，包元数据有 MIT/ISC 不一致；发布前核对真实授权、保留原版权与 attribution，并在 README 标注 Based on ClassroomIO。Phase 0 不擅自改授权字段。
10. **AI/集成边界**：现有多模型与 MCP 专注课程，不等于有 AI 评分或通用培训 webhook；先复用可证实接口，不假设不存在的功能。

## Phase 0 当前结论

本阶段交付八份文档和独立 feature 分支；未写业务代码、未生成 migration、未运行数据库或 E2E。Phase 1 的第一步是复核部署模式、样本数据、已有组织成员与目标环境 migration 状态，再把组织/权限设计落为可运行的最小变更。
