# 至臻内部培训系统：产品与视觉统一规划

日期：2026-09-29。本文保留原始规划；本轮代码实施、运行版本和未通过的验收项见 [实施状态](26-internal-training-implementation-status.md)。

## 1. 参考依据与目标

已在浏览器访问 [公司参考站](http://10.60.6.100/)，页面标题为“至臻集团 · 人才招聘画册”。已查看封面、公司实力内页，并读取页面样式；该站是画册，不能据此推断存在管理后台、业务表格或表单交互。

实际可提取的品牌特征：橙色 Z 标识、白色版面、深色中文标题、浅灰页面背景、橙色细线和少量金色点缀。源码声明品牌橙 `#e85a0c`、深橙 `#b8460a`、亮橙 `#ff8c42`、金色 `#d4a04a`、正文 `#1a1a1a`。封面的图形和内页的衬线大标题适用于品牌展示；业务界面采用适合连续阅读和操作的排版。

本产品定位：河南至臻数字生活科技有限公司内部员工培训系统。围绕培训组织、员工学习、考核处理和培训档案展开。界面简称“至臻培训”，完整公司名称用于登录、关于与必要的文件信息；不因参考站使用“集团”而改写现有公司名称。

本规划更新此前页面方案中关于公开课程站、外部报名和深蓝主导航的方向。前端沿用 Svelte/SvelteKit、Tailwind 和 @cio/ui，继续使用现有路由及数据模型。

## 2. 范围与保留约束

- 保留角色权限体系、考试判分、评分权重、合规完成规则与证书签发规则。
- 保留管理员切换学习端、系统判定学习完成、顶部唯一语言入口、点击弹窗遮罩不关闭等已确认需求。
- 系统默认简体中文，其他已支持的界面语言继续通过顶部入口切换。中文模式不得出现英文兜底、原项目品牌或错误翻译。
- 钉钉接入、员工批量导入和 AI 功能继续排除在本轮实施范围之外，界面不保留误导性主操作入口。
- 保留已有课程、报名、进度与证书数据。收敛入口不等于删除数据或静默更改课程类型。
- 此次只形成方案；未改动参考网站、产品源码、权限配置或现有课程。

## 3. 产品功能取舍

| 当前能力或入口 | 目标处理 | 说明 |
| --- | --- | --- |
| 课程宣传页、页面生成器 | 从内部主流程移除 | 课程详情统一展示基本信息、目录、学习要求、授课人与附件；已有内容保留 |
| 定价、优惠、免费、购买与支付 | 从课程创建、详情、卡片与发布检查中退出 | 内部员工无需理解商品价格；同步检查旧价格校验是否阻断内部课程发布 |
| 公开课程类型、外部报名 | 禁止新增公开招生流程 | 已有公开课程先列清单，再按内部可见范围处理，不直接批量转换 |
| 分享课程、复制公开链接 | 收敛为登录后可访问的内部链接 | 仍须检查组织成员关系、课程资格；持有链接不自动获得报名资格 |
| 课程预览 | 保留管理员预览 | 明确“预览”，不自动产生学习时长、完成记录、考核提交或证书 |
| 课程中心 | 改为内部课程库 | 必修任务通过指派产生；员工选修仅展示企业允许且本人可访问的课程 |
| 培训班、社区、互动组件 | 降为业务需要时出现的二级功能 | 培训班用于实际集训；课程内讨论保留，首页不再以学校社区为中心 |
| 注册、账号邀请 | 以内部管理员开户或邀请为入口 | 自助注册与内部成员资格分开，沿用当前鉴权与邀请校验 |
| 课程评价、讲师介绍 | 收敛为培训反馈、授课人说明 | 退出宣传推荐与营销评价布局 |
| 员工、部门、培训计划、考试、档案 | 作为主流程保留并统一视觉 | 数据口径和操作层级优先于装饰 |

### 访问边界

不能仅删除菜单。实施时逐项检查课程宣传页编辑路由、匿名课程页面、报名/支付入口及对应 API 的真实调用链。旧内部链接应跳转到正确页面，关闭的外部招生链接应显示明确结果。员工不能通过修改 URL、课程 ID 或组织 ID 读取未授权内容。

按既有权限检查组织和课程范围，不重写角色模型。证书验证、密码找回、合法邀请接受等已有独立流程分别核对，避免通过“一律禁止匿名访问”误伤现有能力。没有完成负向测试前，不宣称对外访问已经关闭。

## 4. 两端导航与页面结构

### 管理端

| 一级区域 | 二级内容 | 主操作 |
| --- | --- | --- |
| 工作台 | 待处理事项、在训计划、近期到期、待评分 | 新建培训计划 |
| 课程管理 | 内部课程、课件资源、课程分类 | 新建课程 |
| 培训管理 | 培训计划、人员分配、培训班 | 发布计划、检查进度 |
| 考核管理 | 题库、考试安排、待评分、成绩 | 安排考核、评分 |
| 组织管理 | 员工、部门 | 维护员工与部门信息 |
| 培训结果 | 培训档案、培训矩阵、统计 | 查看明细、按现有权限导出 |
| 系统设置 | 公司信息、角色权限、已有配置 | 按权限维护 |

一级菜单按操作频率排序。子功能只有在页面和接口可用时展示；不为统一菜单而增加空模块。现有 /admin、/org/[slug] 与 /courses/[id] 在视觉上共用管理外壳，进入课程后保留返回位置和清晰面包屑。

### 员工学习端

主导航：学习首页、我的培训、内部课程库、我的考核、培训档案。证书作为档案内的明确入口；个人资料、通知与语言放在顶部公共区域。

- 首页先显示“下一步学习”：课程、所属培训、进度、截止时间和一个主要操作。
- 待办包含已开放待参加的考试、待完成课程、退回任务；即将开放的考试单独标注时间。
- 已有真实封面保留，无图课程使用统一的淡色封面与分类图形；移除重复公司标识、价格与促销标签。
- “开始学习 / 继续学习 / 回顾课程”与真实状态对应。
- 总览区区分待完成课程、已完成课程、已发布成绩的平均分与有效学习时长，单位和统计口径清楚。
- 移动端将待办放在课程列表前，导航可收起，主要按钮保持可见。

### 课程创建与维护

目标流程：填写课程基本信息 → 添加章节与课时 → 设置学习要求 → 核对可见范围及预览 → 发布为内部课程 → 在培训计划中指派。

“线上自学、集中培训、合规复训”描述学习形式；“必修、选修”描述分配要求，不混为同一维度。已有课程类型与后台枚举保留，先检查含义再映射展示名称。创建和发布流程不再要求配置宣传页、定价或对外报名。

### 管理员学习与预览

管理端 / 学习端切换只控制界面，不变更用户角色。管理员被分配为课程参与者时，以本人账号正常学习、考试、计时和归档。管理员检查课程内容使用独立预览语义，不能将查看所有课程的管理权限当作已报名条件。

必须核对课程成员角色、前端学习模式、服务端有效阅读/观看、考试资格和成绩归属是否一致；目前切换按钮通过验证，不代表这条完整业务链路已经验收。

## 5. 视觉规范

采用“白底、至臻橙、深色文字”的整体基调，管理端使用浅色侧栏。深蓝仅在必要的信息图或学习内容中作为辅助色，不再主导整套导航。

| 用途 | 规划值 | 来源与使用方式 |
| --- | --- | --- |
| 品牌橙 | #E85A0C | 参考站源码；图标、选中标记、少量品牌强调 |
| 操作深橙 | #B8460A | 参考站源码；白字主要按钮候选色，实施时验证对比度 |
| 页面背景 | #F5F5F5 | 参考站源码；承载白色业务区域 |
| 内容底面 | #FFFFFF | 参考站实际版面 |
| 正文 / 次级文字 | #1A1A1A / #666666 | 参考站源码；信息层级 |
| 边界 / 选中底色 | #E0E0E0 / #FFF4EB | 前者来自参考站，后者为系统适配提案 |
| 金色点缀 | #D4A04A | 参考站源码；仅用于少量品牌细节，状态含义仍使用文字 |

- 标识沿用用户提供的 Z 图标，统一标签页、登录页、两端导航及占位图规则；实际课程封面不替换为公司 Logo。
- 业务字体使用系统中文无衬线字体，优先 Microsoft YaHei、PingFang SC；不依赖外网字体加载。参考画册的衬线标题仅在登录/企业介绍等低频品牌区域酌情使用。
- 正文 14px，辅助文字 12–13px，页面标题 22–24px，区块标题 16–18px；不在业务表格里使用宣传海报级标题。
- 顶栏约 56px，侧栏约 224px；8px 间距基准，内容边距 24px、手机端 16px；卡片与弹窗圆角约 6–8px。
- 管理列表采用“页面标题与主操作 → 筛选 → 表格 → 分页”；主按钮保持一个，次操作用描边或文字按钮。
- 员工首页采用内容导向布局，任务和课程可用卡片；管理表格不强行套成同样大小的卡片。
- 画册中的大幅装饰 Z、金橙渐变、章节编号、英文副标题只在确有品牌展示需求的区域使用。培训业务不复制 A4 长画册布局。
- 成功、提醒、异常保留有文字含义的状态标识；橙色不承担全部状态。

## 6. 交互与数据规则

- 普通弹窗、侧边表单点击空白不关闭；有明确关闭/取消按钮。大表单提供清楚的保存反馈；关闭存在未保存内容时提示处理。Esc 是否关闭统一遵从明确关闭要求，不静默丢弃内容。
- 下拉选择、筛选气泡等轻量控件可按常规方式收起，不套用阻止所有浮层关闭的规则。
- 表单按基本信息、学习要求、人员范围分组；必填、错误原因、错误位置和提交状态可见。
- 长页面编辑沿用公共保存栏和未保存离开提醒；不再在多个位置放同等级保存按钮。
- 真实零显示 0，未知显示“—”，请求失败显示原因和重试；不得用空数组掩盖错误。
- 课程学习完成、考核通过、培训结业、证书签发分别展示。完成 100% 不能自动推断其他结果。
- 待评分总数按提交记录去重。部门展示分配基数和完成情况，不以小样本推导能力排名。
- 链接、搜索、浏览器返回和刷新均保留正确端、组织和权限上下文。

### 第二阶段：统一公共外壳与两端首页

应用品牌色、中文字体、字号间距和主次操作规范，统一顶栏、侧栏、课程外壳、弹窗和状态展示；完善两端切换后的上下文。

重点文件：`apps/dashboard/src/training.css`、`lib/features/ui/navigation/`、`lib/features/ui/sidebar/`、`lib/features/lms/pages/dashboard.svelte`、`lib/features/org/pages/dashboard.svelte` 及 `/admin` 使用的工作台组件。沿用 @cio/ui 公共组件；新增共享组件按仓库要求补故事，避免每页重复造组件。

第二阶段验收：管理首页 → 课程列表 → 课程编辑 → 学习首页的品牌和层级一致，390px–1920px 无整页横向溢出，管理员与员工可操作范围正确。

### 第三阶段：统一核心业务页面

按课程详情/学习页 → 培训计划 → 考核与评分 → 员工部门 → 培训档案/统计的顺序实施。复用现有业务逻辑，逐页检查汉化、空状态、失败状态和返回路径。

翻译文案使用既有键和词汇表；新增英文源键时按仓库流程同步所有语言，检查占位符。将“学生”改成“员工”时按实际语境处理，保留“参训人员”“讲师”等业务概念，禁止全仓机械替换。

### 第四阶段：真实业务验收与交付

使用本机新环境以及管理员/员工两个测试账号，准备一门有真实内容的课程、一项计划和一场考核，再走完整流程。管理员课程预览、管理员本人被指派学习、普通员工学习三种场景分别验证。

格式/构建通过、浏览器交互通过、真实数据库流程通过分别记录。更新部署时在独立输出目录构建后切换运行版本，避免覆盖正在服务的 build 目录造成旧页面资源失效。提交推送与正式部署按用户授权分别进行。

## 8. 验收清单

- 主导航和课程操作无宣传页编辑、价格、购买、对外报名及原项目品牌残留。
- 中文模式无面向用户的英文残留、错误翻译、原始翻译键；业务创建类型和学习动作清楚。
- 员工仅见本人有资格访问的学习内容，直接访问他人数据与管理 API 被拒绝。
- 管理员预览不产生学习记录；被正式分配后，按普通员工条件记录学习和考试结果。
- 内部课程发布无需配置价格或营销页面；既有权限、评分、合规和证书回归用例通过。
- 待办包含已开放未参加的考试；完成率、时长、评分待办不重复计算、不伪造数据。
- 弹窗遮罩点击不丢输入，关闭/取消/保存反馈可验证，键盘焦点和手机操作可用。
- 登录、两端首页、课程详情、培训计划、考核和档案在 390、768、1440、1920px 检查。
- 一次完整闭环：建课 → 指派 → 员工学习 → 考核/评分 → 查看结果与培训档案；证书只按既有签发条件处理。
