## 二、适合本企业的收敛方向

以下为产品建议，不是行业强制规范，也不是已完成功能清单。

1. **先补流程，再补外观。** 核心验收是“管理员开户 → 备课 → 指派培训 → 员工学习 → 考试阅卷 → 补学补考 → 查档案、导出”，每一步有明确入口、状态和下一步。
2. **后台保留六组入口。** 工作台、人员管理、课程管理、培训管理、考试管理、培训结果；系统设置放低频区域。题库与试卷归考试管理，课件与分类归课程管理。
3. **列表遵循稳定操作结构。** 顶部标题和主要按钮；下方查询/重置与状态筛选；表格中的查看、编辑、更多；勾选后才展示批量操作。操作完成返回原筛选和页码。
4. **首次使用明确准备顺序。** 没有员工时引导导入，没有课程时引导备课，没有题目时引导录题；不得生成假统计让空系统显得丰富。
5. **暂不扩展营销与复杂运营。** 积分商城、红包、付费课程、首页装修、直播运营和 AI 不属于本次核心验收；OA 通知待企业应用授权可用后再接通。

## 五、建议实施顺序

### 第一批：让管理员可以独立完成一次培训

1. **员工入职入口**：中文导入模板、员工字段、逐行检查、明确待激活/已加入状态。先确定现有身份系统允许的开户方式，不能仅去掉邮箱校验或设置全员共用密码。CSV 中文模板可先交付，原生 Excel 导入按实际文件需求增加。
2. **培训发布流程**：基本信息 → 课程与考试 → 指派对象及人数 → 考核规则 → 发布检查。优先组合现有页面和接口；不要为了做向导重写评分规则。
3. **考试工作台**：把已有题目、考试、待阅卷集中可达。先复用课程内考试；若仍必须关联课程，应明确标注，不宣称已实现独立考试。独立考试任务和批量补考另做明确范围。
4. **结果闭环**：未完成/未参加/待评分/未通过名单可钻取，统一导出当前筛选。分页、部门范围与导出权限一起验证。

### 第二批：减少日常维护成本

- 员工列表增加部门树、状态筛选和批量维护；管理员查看单人学习档案。
- 计划按真实需要增加复制、延期、取消/结束与催学；先设计对原有学习记录、考核和证书的影响，再增加按钮。
- 明确计划级结业发证规则；统一证书来源、有效期和发放状态。
- 核对组织管理员与六类企业角色的完整功能权限、部门数据范围及停用行为。

### 后续按需

按入职日期自动滚动指派、线下扫码签到、外部消息送达、知识库等可后续增加。仅有“新员工培训”类型名称不代表已有入职自动化。钉钉继续保持待企业授权状态，AI 保持隐藏；积分商城、营销、付费和复杂装修不进入内部培训核心范围。

## 六、业务验收场景

建议使用隔离测试组织，执行并记录以下结果，不能用构建成功代替。

1. 新建父/子部门；导入正常、重复邮箱、重复员工号、缺字段和未知部门记录；核对成功数与逐行失败数。
2. 新员工从获得账号到首次登录可完成；被邀请但未激活人员的状态准确。
3. HR、培训管理员、部门经理、讲师分别登录；验证可见部门、可执行按钮与直接调用 API 的边界。
4. 指派父部门并切换“包含子部门”；核对去重人数、员工名单与课程访问权限。
5. 培训发布前缺课程、缺考核规则等问题明确提示；正常发布后学员看到正确任务和期限。
6. 学员未开始、学习中、学习完成分别有正确按钮；刷新/换设备后进度与实际学习时长可解释。
