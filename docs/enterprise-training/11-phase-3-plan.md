# Phase 3 培训计划实施清单

基线为 Phase 2 提交 `789126528`。培训计划负责目标、课程、时段和发布；现有 `cohort` 保留为可选班次，课程内容与学习记录继续由 ClassroomIO 原表承担。

## 模型与边界

- 新增 `training_plan`、`training_plan_course`、`training_plan_target`、`training_enrollment`。每个员工在一个计划中至多一条任务；目标命中 ID 和计划版本随发布快照保存。历史成员调岗后不重算已发布名单。
- 目标分别引用同企业有效部门、岗位文本、组织成员；部门目标可选择下级部门。计划课程只能来自同企业有效且已发布的课程。发布时在同一事务内锁定计划、重新解析有效员工、插入去重任务、授予现有课程组学员访问，并更新计划状态。
- 草稿可编辑；发布重复请求返回已发布结果，不重复生成任务。已发布计划的对象和课程先冻结；补录、取消及版本变更放在明确的后续操作，不暗中修改历史任务。
- 尚未注册账号的员工照常获得任务快照；接受组织邀请并关联账号时，在同一事务中补授计划课程访问。
- 学习进度、考核分数及结果不由本阶段虚构；`training_enrollment` 的可空缓存字段留给 Phase 4/6 从原始记录派生。

## 验证

一份兼容 migration；针对部门含子部门、岗位、指定员工的并集去重、离职/停用排除、跨企业课程拒绝、重复发布、课程访问失败时不标记发布及邀请后补授课程访问写测试。在隔离 PostgreSQL 跑完整迁移链，执行 API、dashboard 构建及提交前格式检查。
